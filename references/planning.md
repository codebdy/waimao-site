# 外贸业务与页面规划

## 最少必要输入

从资料中提取企业角色（制造商、贸易商、品牌、OEM/ODM）、产品及参数、主要买家、目标市场/语言、可公开证据、询盘去向。缺少内容不阻止搭建页面结构；真实发布前标明还缺哪些事实。不要一次让用户填写与任务无关的大问卷。

先确定采购商要完成的任务：判断产品适配性、核实供应能力、比较方案、获取文件或索取报价。SEO 关键词服务这些任务。无搜索数据时将关键词建议标为假设，不伪造搜索量或难度。

## 页面组织

| 页面 | 采购决策 | 可使用的信息 |
| --- | --- | --- |
| 首页 | 是否值得继续了解 | 产品方向、服务人群、可信证据、主要入口 |
| 产品分类 | 哪类产品适合需求 | 分类差异、选择标准、产品卡片 |
| 产品详情 | 是否满足规格、如何询价 | 规格、用途、包装、已知 MOQ/交期、真实附件、关联产品 |
| 应用 / 方案 | 如何解决具体问题 | 使用条件、选择方法、产品关联、限制 |
| OEM/ODM / 能力 | 是否能完成定制和交付 | 实际流程、工艺、质量控制、已有案例 |
| 关于 / 质量 | 供应商是否可信 | 可验证企业资料、工厂照片、有效认证 |
| 文章 / 指南 | 如何比较、选择、使用 | 明确问题、证据、作者、相关商业页面 |
| 联系 | 如何提交需求 | 已确认的联系渠道、真实提交结果、隐私说明 |

按业务需要选页面，不要求每个网站都拥有整张表。避免按国家或关键词批量制造仅替换地名的页面。

## 内容与转化

借鉴 Marketing Skills 的价值主张、信息层级、CTA 与信任证据检查，将目标改为有效询盘，而非默认注册或零售结账。

- 每页有一个主要任务和清晰下一步；CTA 文案与实际结果一致。
- 产品资料不足时保留待补充清单，不能用示例参数冒充事实。证书、客户标志、评价、产能、出口国家数和交期都要有来源。
- 没有价格的询盘目录不自动增加购物车，也不填虚构价格满足 Schema 检查。
- 联系方式必须得到确认；没有后台接口时，不渲染会假装提交成功的表单。可使用已确认邮箱作为明确的邮件联系入口，但说明它不是站内询盘系统。
- 已有站点只在用户要求转化改造时修改表单字段、交互和校验。提出建议与实施建议是两件事。
- 本地 static 站已支持多语言，默认仍为单语言；先确定默认语言和实际需要的语言。RXCMS / WordPress 内容源的多语言需要单独接入，不按本地配置直接承诺完成。
- 多语言需处理术语、计量单位、应用限制和实际资料；产品用共享 key 关联各语言版本，各自可有不同 slug。缺少译文时不发布该语言详情页，也不进 sitemap 或 hreflang；切换器可引导到该语言首页。新增语言须补齐界面字典，包括联系、隐私、询盘和 Cookie 文案，不能只改 URL 与 html lang。

如果用搜索工具或 DataForSEO，记录查询市场、语言、时间和证据。付费数据不是必需依赖，不能自动执行计费任务。
