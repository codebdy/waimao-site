# 验证与交付

选择与改动相关的检查，不为文案小修改反复跑完整套件。默认不启动网站、服务、浏览器或后台进程。

## 静态可验证项

- Skill：frontmatter 合法、相对引用存在、无开发机绝对路径依赖、无未知工具硬依赖；借鉴文件有来源和许可。
- Astro：安装版本与锁文件一致，静态检查、相关单元测试和静态构建；枚举生成页面，确认详情、分类和分页完整。
- HTML：解析生成结果检查 title、description、canonical、robots、html lang、内部链接与 JSON-LD；不要用正则替代 HTML/XML/JSON 解析器。
- sitemap 与 robots：内容和索引开关一致，无 404 或 noindex URL；预览与生产设置明确区分。
- CMS：脱敏 fixture 测试字段映射、分页、缺译文、404 与暂时失败；未连真实接口时写清楚。
- 部署：验证 static 不加载适配器、server 选择正确平台、无效配置明确失败。适配器选择单元测试不等于真实平台部署成功。
- static 询盘：检查入口生成/切换、运行时配置、来源与请求校验、失败及未知回执；保存、spam 与通知结果分别测试。当前 RXCMS 不返回普通通知结果，不能伪造 sent/delivered。按客户阶段做真实记录与邮件验收，skill 开发只用脱敏测试。
- Consent：分别验证未同意、拒绝、统计同意、广告同意、撤回、回访及关闭开关；静态测试不能证明浏览器网络或 Cookie 行为。说明手工第三方脚本不在当前控制范围。
- server 构建可能需要平台运行时。若构建会启动本地模拟服务，未经用户允许不执行；报告已做静态检查及尚缺的实际构建/预览验证。
- WordPress API：按脱敏 fixture 检查认证、分页、公开内容筛选、字段/媒体/链接映射、HTML 清理及失败处理；确认凭证只在构建/服务端读取，不声称已完成真实接口联调。

## 需要运行或外部环境才能验证

响应码、重定向、跨域与表单到达、CMS 实际更新、视觉响应式、运行时密钥、平台预览及域名。只有实际观察后才写“已验证”。未经授权不发送测试询盘给真人、不写生产 CMS、不部署生产。

入门指南也需要推演：GitHub 注册与验证、正确 website 仓库、Commit 后 Push、Vercel 登录和仓库授权的区别、Cloudflare 邮箱注册后连接 GitHub、独立根目录选择、CMS 更新不自动触发 Git 部署。整包审核包括代码、文档、fixture、部署示例、开源许可和能力声明。

## 行为场景

零基础场景：用户只提供公司和产品，且不知道安装、后台、平台或终端是什么。检查从取得 skill、安装、触发、准备资料、默认选择、生成网站、用户预览到发布更新的路径是否可走通；每个需要用户操作的步骤是否说清位置、动作、完成标志，是否混淆终端与 AI 对话、skill 目录与网站目录。审核整个 skill 的指令与真实实现，不只润色 README；文档易读不能抵消接口、构建、部署或能力声明的问题。

审核 skill 时至少推演：新站未选内容源时默认本地纯静态且不索要 key；已选 CMS 不重复询问；要求后台但未选 CMS 时询问；已选 CMS 缺凭证时不静默回退；新站未选发布平台；CMS + static 重建；明确 server + Vercel；切换 server 到 Cloudflare；已有 server 站只改 SEO；WordPress API + 环境变量；CMS 失败；多语言缺译文。检查生成 README 的实际选择是否与代码一致，是否保持任务范围、正确表达依赖和未验证项。

交付说明包含实际改动、当前模式/平台、执行的检查及结果、剩余接入步骤。不能把生成模板、静态测试、真实部署混称为完成上线。
