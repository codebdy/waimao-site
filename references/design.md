# B2B 网站设计与组件组织

2026-11-07 改编说明：选取 Anthropic frontend-design 的视觉规划方法、UI UX Pro Max 的风格与排版指导、Vercel Web Interface Guidelines 的网页交互检查，改写为外贸采购场景。来源、固定版本和许可见 [第三方声明](../THIRD_PARTY_NOTICES.md)。这里只整合适用于 B2B 企业展示、产品目录和询盘网站的指导，不包含上游完整 skill、数据库、安装器或运行工具。

## 从采购任务确定视觉方向

先读 [页面规划](planning.md)，利用已有的产品、买家、市场和品牌资料。新建或视觉改造时，在对话中简述推荐的设计方向：主辅色及其用途、标题与正文字体、首页内容顺序、产品图片表现，以及为什么适合这类采购商。用户不懂设计时，用业务语言给出建议并继续实施；只有缺项影响当前选择时才提问，不要求用户填写配色参数或逐项批准。已有品牌规范和明确偏好优先，局部修改沿用现有设计。

下面是可选思路，不是行业固定模板；根据客户资料调整，不凭行业名称强制套配色：

| B2B 场景 | 采购商需要先看什么 | 可采用的视觉处理 |
| --- | --- | --- |
| 工业设备、零部件 | 产品型号、应用、规格与选型依据 | 清楚的分类和参数层级，产品全貌及细节图，重点突出选型与询价入口 |
| 家居、材料、消费品批发 | 系列、材质、款式、包装与定制能力 | 一致的图片比例与色彩呈现，系列导航，场景图与产品图配合 |
| OEM/ODM、定制制造 | 能做什么、工艺、质量控制与合作步骤 | 按实际能力组织内容，用有来源的过程图片说明；只有真实先后流程才编号 |

首页首屏让买家看懂“提供什么、适用于谁、下一步在哪里”。结合真实产品或应用选择主体，不固定为大口号、统计数字和装饰卡片。资料不足时先搭结构并列出待补素材，不能编造认证、客户标志、评价、工厂照片或生产能力。参考站用于理解信息层级和视觉方向，不直接搬用品牌或素材。

## 配色、排版与图片

- 把颜色、字体、间距、圆角和控件状态统一到项目已有 token；主操作有明确视觉重点，次要链接保持可辨认。装饰服务内容，不把每段资料都拆成相同卡片。
- 按品牌与可读性选择字体，通常一至两个字体家族即可；核对授权、目标语言字形和加载成本。有合适系统字体就可沿用，不要求在线字体服务或安装字体包。标题、正文、参数和说明文字应有一致层级。
- 正文保持易读的行宽、行距与对比度。长产品名、型号、单位和长单词可以合理换行；关键规格不能为版面整齐而截掉。颜色不能独自表达错误或选中状态。
- 产品图保持一致的展示比例，保留产品主体、标签和尺寸信息，按内容选择完整展示或裁切。场景图说明用途，技术图和证书须能看清；缺素材时明确待补，不用生成图冒充客户实物或证据。
- 图片声明尺寸或宽高比，按实际显示尺寸提供合适文件；首屏关键图片避免延迟加载，非首屏图片按需懒加载。字体和图片加载后尽量不挤动正文与按钮。
- 动效用于解释展开、切换和提交状态，避免逐段入场遮住产品资料。不默认添加轮播、自动播放视频、滚动接管或动画依赖；确有用途时兼顾暂停、键盘操作和减少动效设置。

## 产品浏览与询盘体验

- 导航和分类使用买家熟悉的名称。产品卡突出可用于区分的真实型号、用途或规格，链接到可直接访问的详情页；目录规模确有需要才增加搜索或筛选，不预设购物车与结账。
- 详情页依采购任务组织图片、规格、应用、附件和询价入口，不要求每页具备没有资料的区块。参数使用语义表格或合适列表；手机上必要的宽表可在有提示的区域内横向滚动，不让整个页面溢出。
- “索取报价”“查看规格”“下载目录”等按钮必须对应已实现的动作；没有附件或询盘接口时不显示假入口。保留已确认联系渠道，不擅自补 WhatsApp、邮箱或响应时效承诺。
- 新建询盘表单只收集处理需求所必需的信息，使用可见标签、合适输入类型和自动填充；允许粘贴，提交中反馈等待，失败说明如何修改或重试并尽量保留输入。具体保存、垃圾判定和通知语义遵循 [询盘契约](inquiry.md)，不把动画完成当成提交成功。维护现有表单时遵守原任务范围，不因视觉检查改字段或接口。
- 导航、菜单、产品图库和表单均应可用键盘操作，按钮与链接使用原生元素。图标按钮有可访问名称，焦点清楚可见；固定询盘按钮与 Cookie 弹窗不能遮挡内容、焦点或彼此。

## 组件与实现

从 kingnod-v2 提炼组织方法：页面壳 → 通用布局 → 业务区块；内容读取与展示分开；SEO 在统一入口输出。不要复制原站品牌、客户数据、照片或来源不明组件。

- 现有项目优先复用其 Container、Section、页头、工具栏、列表和分页组件。新项目先建立一套统一横向轴线、间距与排版 token。
- 列表页标题、筛选和分页使用相同容器。标题默认不加下边框，只有明确分区才添加。
- 表格已有单元格 gutter 时，使用通用表格布局减少外壳内距，同时保留统一小幅侧边距；不要在业务页用零散 px / margin 补齐。
- 桌面、手机及中间宽度都应有可用导航；kingnod-v2 某些已接受的平板限制不是通用规范。
- 默认静态 HTML，确有交互才增加客户端脚本。无需为普通导航、产品卡和文本引入 React。
- 图片优化采用项目已有工具；减少动效时尊重 prefers-reduced-motion。
- starter 的配色是中性演示，不能把起步模板直接当成最终设计。

## 设计复查

实施前对照客户资料检查设计理由；完成后按 [验证与交付](verification.md) 复查：主要采购任务是否突出、真实资料是否清楚、长内容和缺图片时是否仍可用、手机上能否找到产品和询盘入口。不要只凭套用了某种风格就报告设计合格。

视觉验收需要用户启动后的浏览器或明确授权。在有运行页面时查看手机、中间宽度和桌面布局，以及文字放大、键盘操作和表单反馈；没有运行页面时只报告结构、编译和可检查的语义属性，不声称视觉或交互已验证。
